WHAT THIS SAYS, and both halves are findings rather than notes.

1. 91 of 3231 cases reach an arm at all. 3032 sit at AWC_Mode = -600, the
   inert value the generator holds a scalar at when no rule is varying it, and
   the rest are R6's integer ladder -- decade boundaries and the two 32-bit
   extremes -- none of which is 1..5. The five live modes come from R6's
   predicate cross-product (AWC_Mode x AWC_NumModes x NumBl x Time), which is
   the ONLY block that puts this unit's own switch on a value it branches on.
   The no-op red test fails 86 of the same 3231, five short of 91: five live
   cases in which the reference's writes land on values the inert state already
   held.

2. NO CASE IN THE CORPUS HAS AWC_harmonic(1) == 0, and neither does any of the
   27 gate scenarios. That guard appears twice --

       :803-:806  the TiltMean accumulation and StartTime = 1/AWC_freq(1)
       :829-:830  PitCom(K) = PitCom(K) + AWC_TiltYaw(1)

   -- and BOTH arms are outside every instrument this campaign has. The cause
   is not the range pins: `AWC_harmonic` is an ALLOCATABLE INTEGER array and
   `generate._fill_array` ramps it across the defaulted +/-1e3 bounds, so
   element 1 is about -600 in every case. It is not a knob either: the
   reference's predicate is written against `AWC_harmonic(1)`, a constant-
   subscript element of an array parameter, and the knob extractor takes
   scalars. A `lo`/`hi` pin cannot repair it, because the ramp is monotone --
   any bound that puts 0 in the array puts it at element 1 in EVERY case, which
   would delete the ELSE arms that all 27 scenarios do exercise. What is needed
   is a knob, and that is a change to the generator, not to ranges.toml.
