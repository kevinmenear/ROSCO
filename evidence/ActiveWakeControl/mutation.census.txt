MUTATION SURVIVOR CENSUS -- unit #47 ActiveWakeControl

mutation/ActiveWakeControl.json: 165 killed of 210 behavioural, 14 no-compile,
224 mutants offered, 0 declared equivalent, score 0.7857 against a threshold of
1.000. Every one of the 45 survivors is listed below, grouped by the ONE fact
that explains it, and every fact is a MEASUREMENT taken on the corpus the score
was computed over -- not an argument about what the corpus probably contains.

The two probes those measurements come from are
evidence/ActiveWakeControl/harness.arm_census.txt (AWC_Mode, AWC_harmonic) and
evidence/ActiveWakeControl/harness.live_case_inputs.txt (the rest). Both are one
fprintf into the GENERATED test source, relinked with `harness.sh --no-generate`
so the corpus is the scored one, and both report INPUTS only, which is why
neither needed a reset window.

NOTHING IS DECLARED EQUIVALENT. This campaign's rule is that a declaration rests
on a measurement, and for eight of these ten groups the measurement says
'unreachable in this corpus', which is a statement about the corpus and not
about the program. Declaring those would convert a corpus weakness into a
score. Same standing as interp2d at 0.9744 and unwrap at 0.960: P12 is left
failing on purpose.

G5 -- CntrPar%AWC_phaseoffset IS 0.0 ON THE WHOLE REACHABLE DOMAIN.  4 survivors

MEASURED: `phaseoff=0` in all 91 live cases. `0.0 * D2R`, `0.0` and `0.0 / D2R`
are the same bits, so the three sites that pass `AWC_phaseoffset * D2R` to
ColemanTransformInverse cannot tell the three apart. This is an equivalence ON
THIS CORPUS and not in the program: any non-zero phase offset separates them.
THE INPUT THAT KILLS THEM: AWC_Mode in 2..5 with AWC_phaseoffset /= 0.

G8 -- A DEAD STORE THE PINNED DOMAIN MAKES DEAD.  2 survivors

`AWC_TiltYaw = [0.0, 0.0]` at the top of the mode-2 arm is overwritten before it
is read: the loop below writes `AWC_TiltYaw(Imode)` for Imode = 1..AWC_NumModes
and, when AWC_NumModes == 1, writes element 2 as well. `CntrPar_AWC_NumModes` is
pinned to [1, 2] in harness/ranges.toml, so both elements are always rewritten
and moving either reset to another element changes nothing. THE PIN IS WHAT
MAKES THIS TRUE: at AWC_NumModes == 0 the reset is the only writer, and that is
the value the pin removes -- for a different reason (an uninitialised
`AWC_angle` read), stated there.
THE INPUT THAT KILLS THEM: AWC_Mode == 2 with AWC_NumModes == 0, which is
outside this corpus by a pin whose own cost is recorded in ranges.toml.

G10 -- ADDING AND SUBTRACTING A ZERO PARAMETER.  1 survivor

`phi1` is `REAL(DbKi), PARAMETER :: phi1 = 0.0`, so `Azimuth + phi1` and
`Azimuth - phi1` differ only when Azimuth is negative zero, and even then only
until `clockang` is added: `-0.0 + 0.0` and `-0.0 - 0.0` are `+0.0` and `-0.0`,
and adding any non-zero clockang collapses them again. The corpus varies
Azimuth on the +/-1e3 default and no case presents -0.0 for it.
THE INPUT THAT KILLS IT: Azimuth == -0.0 with clockang == -0.0 and
omega*Time == 0, in mode 1 with NumBl >= 1.
