ONE case at `cap == need`, and that is R13's design rather than luck: the whole
256-case block is `cap_base` copied with one headroom per case and EVERY OTHER
INPUT AT ITS BASE DRAW, so the output has one length across the block and
exactly one capacity sizes the buffer to it. The block's own diagnostics are
visible in the harness run --

    VIT: CableControl: ErrVar%ErrMsg needs 26 bytes, the staging buffer holds
         17..25; the assignment is refused
    VIT bridge: ErrVar%ErrMsg assignment of 26 bytes exceeds the 17..25-byte
         buffer the caller supplied; left unchanged

-- one line from each chain at each of the 18 capacities below `need`, which is
the shape unit #48's `staging_capacity_excludes` exists for and which this unit
does NOT need: its two chains agree there because only ONE assignment is staged.
`interp1d` is the callee that could stage a second, and it is reached only on
the `CC_Mode == 2` arm, which the R13 block does not take (`CC_Mode` is at its
base draw of -300 throughout).
