FIVE OF THE TWELVE WERE ONE FACT ABOUT `SecLPFilter_Vel`, AND IT WAS NOT THE FACT
THE FIRST READING SUGGESTED
--------------------------------------------------------------------------------

The two PIController gains looked like a saturation story: `-1000.0 -> -1001.0`
was killed on 1703 cases and `1000.0 -> 1001.0` on 1, so the integrating arm was
plainly being reached and clamped, and a gain that changes nothing inside a clamp
is an ordinary corpus gap. That reading is WRONG, and the thing that decides it is
the reference's own control flow rather than the kill counts:

    Filters.f90, SecLPFilter_Vel
      IF ((iStatus == 0) .OR. reset) THEN
          ... the six lpfV_ coefficients are computed HERE and only here ...
      ENDIF
      SecLPFilter_Vel = 1.0/FP%lpfV_a2(inst) * ( ... )

`LocalVar%FP` is a nested type the generator ZERO-INITIALISES and does not vary --
the harness prints it as `UNOBSERVABLE LocalVar.FP: nested type, zero-initialised
(not varied) and compared bytewise after the call`. So on every case with
`iStatus /= 0` and `restart` false the divisor is 0.0, the filter returns
`Inf * 0.0` = NaN, and the NaN propagates through `PIController` into
`CC_ActuatedDL`, `CC_ActuatedL` and `avrSWAP`. `kp*error` is NaN whether kp is 0.0
or 1.0. Confirmed in the first take's own red-test output, which prints the
reference's `CC_ActuatedDL(1)` for case 0 as `000000000000f87f` -- a quiet NaN.

And where the corpus DID initialise the filter it did so through `restart`, which
is the SAME value this unit hands `PIController` as its `reset` -- and that arm
assigns `I0` and reads neither gain. So the one configuration in which either gain
can reach an answer is `iStatus == 0` with `restart` FALSE, and no rung of any
ladder crosses those two names. All three baseline states carry it.

THE THREE STANDING SURVIVORS ARE ALL (b), AND THE MEASUREMENT IS SEPARATE
-------------------------------------------------------------------------

All three are in the two copied ErrMsg helpers; not one is in the arithmetic.
`evidence/CableControl/errmsg_census.txt` gives, over the SCORED corpus, the
input each one needs and the count of cases that hold it: 0, 0 and 0.
`evidence/CableControl/mutation.green_kill_probe.txt` then answers the question
that DECIDES the disposition -- is there any input with ORIGINAL == REFERENCE and
MUTANT != REFERENCE -- by executing both chains over 100,100 configurations
rather than arguing it: 385, 376 and 1128 green kills, negative control 0,
positive control 46,130, and `separates == kills` for all three, so not one
separating input lies where the two chains already disagree. All three are (b);
none is unit #48's (c). The cause is a single fact: this unit's base draw is
`aviFAIL = 300` and `CC_Mode = -300`, the midpoints of the +/-1e3 default, so
R13's whole 256-case capacity block and R6's character-length rungs sit where
`IF (ErrVar%aviFAIL < 0)` is false and neither helper is entered at all.
