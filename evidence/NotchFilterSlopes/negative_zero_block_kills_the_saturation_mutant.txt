What the NEGATIVE-ZERO corpus block bought, measured on this unit
=================================================================

The survivor
------------

  38bbc289  compare_op   'if (CornerFreq < 0)'  ->  'if (CornerFreq <= 0)'

the saturation guard NotchFilterSlopes opens with. It was the ONLY mutant alive
after a 4468-case green differential run.

The two predicates disagree on exactly one input, CornerFreq == 0. At +0.0 the
two branches produce identical bits, so no amount of magnitude coverage can
separate them. The witness is NEGATIVE zero, and the corpus could not hold one:
`harness/generate.py`'s `_real_magnitude_ladder` and `_ladder` both end in
`list(dict.fromkeys(out))`, and `0.0 == -0.0`, so a `-0.0` written into either
list is absorbed by the `0.0` already there. Every other rung this generator has
ever gained could be added where it belonged. This one could not, which is why
it went in as a block appended last rather than as an entry.

Not equivalent -- proved, not argued (evidence/NotchFilterSlopes/negative_zero_survivor_probe.*)
------------------------------------------------------------------------------------------------

  CornerFreq = +0.0    differ  0 of 36
  CornerFreq = -0.0    differ 36 of 36    first differing output: nfs_b2

  witness  InputSignal=1.0  DT=0.0125  CornerFreq=-0.0  Damp=0.7
    reference nfs_b2 = -0   bits 8000000000000000
    mutant    nfs_b2 =  0   bits 0000000000000000
    reference nfs_b0 =  0   bits 0000000000000000
    mutant    nfs_b0 = -0   bits 8000000000000000
    return value      AGREES

The last line is the sharper half of the finding. In all 36 differing draws the
RETURN VALUE is bit-identical, because IEEE addition collapses (+0.0) + (-0.0)
to +0.0. A differential harness comparing only the unit's result could not have
killed this mutant at ANY input; it is reachable only because
R4_compare_all_outputs compares the coefficient out-parameters too.
