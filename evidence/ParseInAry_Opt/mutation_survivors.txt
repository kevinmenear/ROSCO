REGION E -- ONE MUTANT WHOSE DISTINGUISHING RECORD HAS NO ORACLE
-----------------------------------------------------------------

    07b5ee72  negate_cond  L258  `if (is_eol(rec[p]))` negated, inside
                                 `eat_separator`'s blank scan

The mutant makes a BLANK look like an end-of-line, so `crossed_eol` is set where
the shipped program leaves it clear. `crossed_eol` is read at exactly one place:

```
270:            sep = crossed_eol ? Sep::Eol : Sep::Blank;
298:            if (first_item || sep != Sep::Blank) { return 5010; }
```

and L298 is the SEMICOLON guard. So the only records that can separate the two
programs are records in which a `;` starts an item and was reached across
blanks -- and on those records the shipped program treats the `;` as LEGAL,
which is to say as a NULL VALUE. **A null value leaves its element of a freshly
ALLOCATEd `Ary` undefined while the reference returns IOSTAT 0**, and the two
sides then differ on recycled heap rather than on anything either implementation
decided.

The direction matters and closes the search rather than leaving it open. To kill
the mutant the harness needs the ORIGINAL to return 0 and the mutant to return
5010 (or the reverse), and:

  * original 0 / mutant 5010 requires the `;` to be legal for the original,
    which is the undefined-element case above;
  * original 5010 / mutant 0 would require the mutant to make a `sep` that is
    NOT `Blank` become `Blank`, and the negation only ever moves `sep` the other
    way (`Blank` -> `Eol`) on a record with no end-of-line character in it;
  * a record carrying a real `\\n` or `\\r` would move it the useful way, and
    `FileLines` elements come from a file reader that cannot produce one.
  * both non-zero is INVISIBLE: `aviFAIL` is `-1` and `ErrMsg` is the same
    parse-error text for `5010` and for `-1` alike, because the message is
    written from the BRANCH and not from the number. That is the same fact
    section 1 of `equivalences.md` rests on, used here to show a kill is
    impossible rather than that a mutant is equivalent.

So this is case (c) and it is the SAME (c) as the six `unreachable`
declarations: an input region the reference is undefined on. It is NOT declared
equivalent -- the two programs genuinely differ on `0 ;`, and the third
dispatch's record search measured that difference over 22 records
(`survivor_record_search.txt`) -- and it is NOT declared unreachable, because L258
IS executed by this corpus: `line_coverage.txt`'s never-executed list holds
L259 -- the `crossed_eol = true;` inside the `if` -- and not the `if` itself,
which is exactly the shape a line-granular claim cannot make. It is left in the survivor list, where it costs the
score one mutant and says what it costs it for.
