The question worth a gate run has moved with the score. Six mutants are now

THE POSITIVE CONTROL IS ON THE SAME BUILD AND IS ALREADY IN THE TREE. A zero on
its own cannot be told from a gate that does not reach the unit;
`gate/ParseInput_Dbl_Opt.redtest.parsed-value.json` perturbs the value this same
function parses, on this same build, and moves 1,857,893 of 5,252,000. So the
gate demonstrably observes this unit's output.

1. 8e796788   match_word   `for (std::size_t k = 0; ...)` -> `k = 1`

   Skips the comparison of the IEEE word's FIRST character, so `match_word`
   accepts a strict SUPERSET: any field whose 2nd and 3rd characters spell
   `nf` or `an` (or 2nd..8th `nfinity`) matches even when the first is not
   `i`/`n`.

   PREDICTED: EXACTLY 0 of 5,252,000. Every first word of `Examples/DISCON.IN`
   read by this unit is an ordinary decimal literal -- `4.30935e+04`,
   `0.00000e+00` and the like -- and none has `nf`/`an` at characters 2-3.

2. 575c6151   match_word   `p + static_cast<int>(word.size())` -> `p - ...`

   Removes the bound that stops `match_word` reading past the record. It can
   only differ where a value begins within `LEN(word)` bytes of the record's
   last byte -- byte 193 or later of a 200-byte `Words(1)`.

   PREDICTED: EXACTLY 0 of 5,252,000. `GetWords` LEFT-JUSTIFIES every word into
   `Words(1)`, so the value begins at byte 0 (or byte 1 after a sign); the only
   way it starts near byte 200 is behind a ~190-digit repeat count, which no
   line of `Examples/DISCON.IN` carries.

A non-zero on either would refute a declaration this dispatch made, and that is
the outcome the runs are for.
