WHAT EACH IS FOR, at the level of the one character that does the work
------------------------------------------------------------------------------

`e8cf2d25`  `:261`  `is_eol(rec[p])` -> `is_eol(rec[p + 1])`

    The leading scan is `is_blank(rec[p]) || is_eol(rec[p])` and `||`
    short-circuits, so the mutated operand is evaluated ONLY at the character
    the scan stops on. Every record in the 12,199-case corpus begins with a
    digit, a sign or a letter, and the byte after it is another such -- so both
    spellings read "not an end-of-line" and agree.

    `eollead` = CR then `7`. Original: crosses the CR, parses 7, status 0.
    Mutant: at p = 0 `is_blank(CR)` is false and `is_eol('7')` is false, so the
    scan does not run; the item loop then meets the CR, which is not `/`, not
    `,` and not `;`, and `parse_int` finds no digits -> 5010.
    PREDICTED: status 0 with Variable = 7 against 5010 with `aviFAIL = -1` and
    an ErrMsg. The unit sees all three.

`4f89b00b`  `:288`  `p >= len` -> `p > len`

    `p == len` at the top of the item loop happens only when the leading scan
    consumed all 200 bytes -- every byte a blank or an end-of-line. A record of
    all blanks is not a WORD, so no word splitter produces one; a record of all
    CRs is a word, because CR is not in `GetWords`' separator set.

    `eolfull` = 200 bytes of CR with `/7` as word two, so record byte 201 is a
    `/`. Original: `200 >= 200` -> END, status -1. Mutant: `200 > 200` is false,
    so it reads `rec[200]` = `/` and returns 0 with the item untouched.
    PREDICTED: -1 against 0, which the reference's `ErrStatLcl /= 0` sees.

    THE NEIGHBOUR IS THE DESIGN. With any other byte there both spellings end
    non-zero (5010 against -1) and a caller reading only `/= 0` cannot tell
    them apart. This is the same shape as round 2's `repzeroslash`.
