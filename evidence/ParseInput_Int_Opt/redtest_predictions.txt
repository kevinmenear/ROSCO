THE ADDITIVE CONTROL FAILED, AND IT IS REPORTED RATHER THAN CLAIMED.

    old case file  6,022,734 bytes
    new case file  6,044,700 bytes
    old is a PREFIX of new:  False

Unit #56's rule is to take `b[:len(a)] == a` on every corpus-extending change,
and it is taken here. It does NOT hold, and the reason is structural rather than
a slip: the entries were added to `_NEIGHBOUR_VALUES`, which is consumed inside
the `n:` block that R14 appends after EVERY plant index, so new cases from the
k = 1 block displace everything the k = 2 and k = 3 blocks emit after it. There
is no ordering of that tuple that makes the change a suffix append.

So this is a DIFFERENT corpus, not an extended one, and every layer that reads
the corpus was re-taken on it -- harness, partition, all four stubs, line
coverage, both mutation sweeps. Nothing carries over from the 11,863-case run
except the mutant IDs, which are a function of the translation and not of the
corpus.
