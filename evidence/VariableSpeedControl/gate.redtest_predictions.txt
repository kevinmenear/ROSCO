RT1 -- THE RETURN PATH.  `gate/VariableSpeedControl.redtest.return_path.json`

    rosco/controller/src/variablespeedcontrol.cpp:623
      from  avrSWAP[47 - 1] = static_cast<float>(std::fmax(0.0, LocalVar->VS_LastGenTrq));
      to    avrSWAP[47 - 1] = static_cast<float>(std::fmax(0.0, LocalVar->VS_LastGenTrq) + 1.0);

ADDITIVE, NOT MULTIPLICATIVE, and the reason is unit #46's: `MAX(0.0, x)` is
exactly 0.0 whenever the demanded torque is non-positive, and a scale through an
exact zero is a no-op. `+ 1.0` moves every call including those.

`avrSWAP(47)` is the one value this procedure exists to produce -- the demanded
generator torque -- so this is the widest channel the unit has, and it feeds the
drivetrain, hence `gen_speed` and `gen_power` as well as `gen_torque`.

    PREDICTED  NON-ZERO, and LARGE.
    PREDICTED  scenario set EXACTLY the 23 above; NOTHING in 10, 13, 14, 24.
    The scenario set is the checkable half; the value count is not predicted to
    a number, and saying so is the point (unit #59: the scenario count is a
    separate prediction from the value count).

MULTIPLICATIVE here on purpose. `VS_KOmega2_GenTq` is `VS_Rgn2K * GenSpeedF *

1.0e30 is chosen so that the prediction has no hiding place: if any scenario
reached this statement the torque would leave every plausible range and the
mismatch count would be enormous. A zero here is what separates "the gate sees
this unit" (RT1, RT2) from "the gate sees the edit".
