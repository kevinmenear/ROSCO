WHAT THE KERNEL COMPARES, AND WHAT IT DOES NOT
--------------------------------------------------------------------------------
419 field names, 26,040 rows. `gentq`, `genartq`, `genbrtq`, `gentq_sd`,
`vs_maxtq`, `vs_komega2_gentq`, `vs_constpwr_gentq`, `vs_lastgentrq`,
`vs_lastgenpwr`, `instpi`, `instrl`, `avifail` and `vs_state` are all in it --
and NINE of those are outputs no gate channel reads directly, which is the whole
reason this layer was taken after the gate.

NOT in it: `avrswap` (assumed-size, skipped by KGen's comparator -- stub 2 below
measures exactly that), and the nested `piP` / `rlP` parameter blocks, which
appear under no field name at all. So a defect confined to the callee state this
unit hands to `PIController` and `ratelimit` is invisible here; `instpi` and
`instrl`, the counters that INDEX those blocks, are visible.

STUB 2 IS THE BLIND SPOT, MEASURED RATHER THAN INHERITED. Deleting
`avrSWAP(47) = MAX(0.0_DbKi, LocalVar%VS_LastGenTrq)` -- the demanded generator

WHAT THE KERNEL LAYER DOES NOT COVER
--------------------------------------------------------------------------------
* `avrswap` -- stub 2, measured above.
* the nested `piP` and `rlP` parameter blocks, which appear under no field name
  in the 419. `instpi` and `instrl` (the counters that INDEX them) are compared,
  so a mis-sequenced call is visible; a wrong value written INTO a slot is not.
* every arm scenario 12 does not take. All 60 cases have `VS_ControlMode == 1`,
  `VS_FBP == 0`, `VS_ConstPower == 1` and `SD_Trigger == 0`, so this layer sees
  the K*Omega^2 law and NOTHING ELSE: not the tip-speed-ratio PI arm the other 22
  scenarios take, not the shutdown ramp (scenario 9), not the open-loop block,
  and not Regions 2.5, 3-constant-torque, 3-constant-power or 3-FBP.
* the differential harness is the layer that would have reached those, and it
  could not be built -- `corpus_wall.txt`.
