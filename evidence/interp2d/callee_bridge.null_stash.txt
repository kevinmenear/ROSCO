# THE CAMPAIGN'S FIRST DIFFERENTIAL HARNESS WHOSE CALLEE TAKES A VIEW TYPE,
# and the generated bridge dereferenced a null module pointer on case 0.
#
# `interp2d` calls `interp1d`, which takes `TYPE(ErrorVariables), INTENT(INOUT)`.
# On a clean tree `scripts/harness.sh` KEEPS the generated `interp1d_c` bridge,
# so that both sides of the comparison reach one callee. That bridge reads:
#
#     CALL C_F_POINTER(ErrVar, ErrVar_view)
#     CALL vit_copy_scalars_to_errorvariables(ErrVar_view, vit_original_errorvariables)
#     bridge_result = interp1d(..., vit_original_errorvariables)
#     CALL vit_populate_errorvariables(vit_original_errorvariables, ErrVar_view)
#
# and `vit_errorvariables_view.f90` declares
#
#     ! Kernel stash: pointer to original Fortran type, set by wrapper before calling C++.
#     TYPE(ErrorVariables), POINTER, SAVE :: vit_original_errorvariables => NULL()
#
# THE WRAPPER IS THE THING THE DIFFERENTIAL HARNESS DOES NOT HAVE. It calls the
# translation DIRECTLY, so nothing ever sets the stash.
#
## measurement 1 -- what the crash was
#
#     ./test interp2d_cases.bin        Segmentation fault (core dumped), rc 139
#     no stdout at all: the harness prints its JSON after the loop
#
# Located by three instrumented rebuilds, each one narrowing the window:
#     "CASE 0 A"                       the C++ side, case 0
#     "P3b gathered 3: ..."            past the row gather
#     (nothing after)                  inside interp1d_c
#
# and then settled by asking the pointer directly, in the bridge:
#
#     WRITE(0,*) 'BRIDGE stash associated =', ASSOCIATED(vit_original_errorvariables)
#     BRIDGE stash associated = F      <- the first call
#     BRIDGE stash associated = T      <- every call after the hand patch
#
## measurement 2 -- why the stash alone is not the fix
#
# With `vit_original_errorvariables => <a local target>` and nothing else, the
# run completes and reports
#
#     checked 1117  failed 123  inadmissible 0
#     case   0  ErrVar.n_ErrMsg   ref 07000000  !=  got ffffffff      (-1)
#     case 429  ErrVar.ErrMsg     ref 'interp1d:9:@ABYZ' != got '9:@ABYZ'
#
# Both existing converters move a deferred-length CHARACTER field through the
# MODULE STAGING BUFFER, which only a wrapper's own `vit_populate_<t>` fills --
# so the copy IN silently left the field alone, and the populate on the way OUT
# REPOINTED `view%ErrMsg` away from the buffer the caller owns and set its
# length to the NOT-ALLOCATED sentinel.
#
## the fix, in VIT, additively (X2: the tool is ours)
#
#   vit/view_populator.py    generates `vit_direct_<t>` and the pair
#                            `vit_view_in_<t>` / `vit_view_out_<t>`, which
#                            convert against the CALLER'S OWN buffer and leave
#                            its pointer and capacity alone. A field kind
#                            neither handles is an ERROR STOP naming it.
#   vit/interface_gen.py     the callee bridge takes the direct path only when
#                            `.NOT. ASSOCIATED(<stash>)`, and NULLIFYs after, so
#                            a later wrapper-driven call re-detects.
#
# Nothing existing changed: the regenerated `vit_errorvariables_view.f90` is
# byte-identical up to the additions, and when a wrapper HAS set the stash no
# new statement executes.
#
## after
#
#     HARNESS PASS: checked 1005  failed 0  inadmissible 0
