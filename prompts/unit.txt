LONG WORK, IN ORDER. These are not five rules to reconcile -- they are one
procedure, and every step exists because a unit of this campaign was lost at it.

1. COMMIT WHAT YOU HAVE BEFORE YOU RESET. `scripts/reset_to_clean.sh` reverts
   every integrated unit's Fortran so a measurement sees the real reference;
   `scripts/restore_integrated.sh` puts it back. Between them a pre-commit hook
   REFUSES every commit, because a commit there would record the whole campaign
   as de-integrated. That refusal is expected, not an error -- and if you reset
   with work uncommitted, you cannot commit it until you restore.

2. RUN LONG WORK IN THE FOREGROUND AND LET IT BLOCK, AND ASK THE CLOCK FIRST.
   Do not background it. Do not poll it. **And do not announce that you are
   waiting for it, because nothing will wake you** -- there is no timer, no
   notification and no further input, so a session whose last act is "I will
   wait" simply ends, and the driver assesses it as having done nothing.

   A backgrounded sweep is worse than a wasted session: it OUTLIVES you. It
   orphans inside the container, keeps running after the driver has moved on,
   and writes into the campaign tree minutes or hours later, against a tree that
   has since been restored. Two units of this campaign did exactly this.

   Backgrounding is safe only for work the HARNESS tracks and re-invokes you
   for. A `docker exec` is not that. Neither is anything you launch with `&`.

   The shape to never write:

       for i in $(seq 1 60); do ... ; sleep 10; done   # against an output file

   Foreground and block instead. The command returning IS the notification.

   AND ROUTE ANYTHING LONG THROUGH THE CLOCK, with a seconds estimate:

       bash scripts/run_if_time_remains.sh 600 <the command>

   It refuses, without starting the command, if that much time does not remain.
   Splitting work by operator does not help if the last piece is begun too late
   to finish. Take the refusal: commit what is measured, say in your final
   message which pieces were NOT taken, and let the next dispatch take them. A
   named gap is worth more than a killed sweep.

3. EVERY MUTATION SWEEP GOES THROUGH THE MARKER. `vit_mutate.py` edits the
   translation IN PLACE and restores it on completion; killed, it does not, and
   three of three hard kills have left a mutant behind. Never invoke it bare:

       bash scripts/mutate_guarded.sh translations/<Module>/<stem>.cpp \
           <the docker exec vit_mutate.py command>

   If it exits 3 it has found a mutant live in the translation. Follow its

4. RESTORE AS SOON AS THE CLEAN-TREE MEASUREMENT IS DONE, before anything else.

5. THEN COMMIT, and commit EACH expensive artifact as it exists from then on --
   the translation, the harness result, the mutation result, the gate result,
   the evidence. Not one commit at the end.

EVERY MUTANT GETS AN ANSWER, AND THERE ARE NOW THREE OF THEM. The bar is not
"kill every mutant", it is EXPLAIN every mutant. P12 divides by
`mutants - equivalent_declared - unreachable_declared`, so an explained mutant
leaves the ratio instead of dragging it down. For each survivor, pick one:

  KILL IT.        Usually the corpus is too narrow, not the translation wrong.
                  Fix the inputs, not the record.

  EQUIVALENT.     The two programs agree on every admissible input. A claim
                  about the PROGRAMS. `--equivalences <file>`, a JSON list of
                  ids, with the reasons written where they can be disputed.

  UNREACHABLE.    The corpus cannot reach it, and you can show that. A claim
                  about the CORPUS -- cheaper to assert, so it is checked
                  harder. `--unreachable <file>`, a JSON OBJECT:

                      {{"<id>": {{"reason": "<why no case reaches it>",
                                 "evidence": "<path that shows it>"}}}}

                  Both fields are required and the evidence path must EXIST or
                  the run is refused before a mutant is built. Declare one the
                  corpus then kills and P12 fails the unit outright -- so
                  declare what you proved, not what you suspect.

IF YOUR SURVIVORS ARE OUT-OF-BOUNDS READS OR WRITES, RE-RUN THE SWEEP WITH
`--sanitize`. It builds the mutants with `-fsanitize=address,undefined`, which
reaches the class no corpus can: a mutant whose only difference is at addresses
the program does not own is invisible to a value comparison, and three
identical runs over one such mutant scored 0.983, 1.000, 0.983 -- the 1.000 is
the run that measured least. `p < len` becoming `p <= len`, `rec[p]` becoming
`rec[p+1]`, and index_offset survivors generally are the shape that wants it.

A SANITISER BASELINE THAT REPORTS ON THE UNMUTATED TRANSLATION IS A FINDING,
NOT AN OBSTACLE. `vit_mutate.py --sanitize` refuses to score when the clean
build already reports, because every mutant would then "die" of the original's
own defect. Do not route around the refusal: it has found a real bug in the
translation or in the harness, and that bug is worth more than the sweep.
